# Управление аффирмациями

Тестовая ветка feature/affirmation-history основана на рабочем коммите
d1a4860814cb1492adfda0174bfffef6a856b141. Выпуск требует отдельного разрешения.

В меню добавлена кнопка «Аффирмации». Команды /affirmations и /affirm
без текста открывают тот же раздел. Он показывает текущий текст, дату его
начала и будущие записи. Для каждой будущей записи доступны «Изменить» и
«Отменить». Список разбит на страницы по пять записей.

Нажмите «Новая аффирмация», введите текст, затем дату (ДД.ММ.ГГГГ,
ГГГГ-ММ-ДД или «сегодня»). Бот покажет текст и дату с кнопками
«Подтвердить», «Исправить», «Отменить». /affirm Текст начинает тот же
процесс с шага выбора даты. /cancel отменяет черновик.

После исправления нужно снова ввести текст и дату, затем подтвердить.
До подтверждения история не меняется. Повторное или одновременное нажатие
на подтверждение одного черновика не добавляет вторую запись.

Новая запись может вступить в силу сегодня или в любой будущий день.
При более ранней смене позднейшие планы сохраняются. Например, запись
на 25 ноября действует до 30 ноября включительно, а существующая запись
на 1 декабря начинает действовать с 1 декабря. Предпросмотр предупреждает
о следующей запланированной смене.

Если на выбранную дату уже есть запись, прежняя версия помечается
superseded и сохраняется в истории. При отмене будущей записи она
помечается cancelled. Утренний план пропускает обе эти категории и
выбирает самую позднюю действующую дату. Отдельная дата окончания не нужна.
Прошедшие записи через интерфейс будущих планов не редактируются.

Рабочее время — Europe/Moscow. Если новая аффирмация назначена на сегодня
после уже отправленного утреннего плана, повторное утреннее сообщение
не отправляется. Новый текст виден в разделе и используется следующим
утром, если к тому дню не наступил следующий план.

Хранилище — существующая колонка planner_state.affirmations_history,
id=1. app.py блокирует строку на время обработки, пишет историю только
после её изменения и сохраняет изменение вместе с состоянием и очередью
ответов в одной транзакции. Чтение списка и создание черновика не
перезаписывают историю. Другие колонки сохраняют прежнюю структуру.

При пустой истории прежний data.affirmation остаётся резервным текстом.
На первой подтверждённой записи он переносится в историю с датой дня
переноса и source=legacy. Эта дата обозначает перенос, историческая
дата начала старого текста неизвестна. Старое поле сохраняется.

Совместимый откат подготовлен в scripts/prepare_rollback.py. Он экспортирует
предыдущий рабочий коммит d1a4860814cb1492adfda0174bfffef6a856b141 и меняет
только выбор аффирмации, добавляя учёт статусов cancelled/superseded.
Генератор проверяет ожидаемый фрагмент исходника и создаёт только новый каталог.
Ветка и рабочая копия git при подготовке не переключаются.

Откат выполняется выпуском подготовленного кода. История и другие данные
в PostgreSQL продолжают использоваться в текущем состоянии. Копия старой
базы не восстанавливается поверх новых записей. Предыдущий интерфейс
Telegram после отката имеет прежние возможности, а выбор утреннего текста
продолжает учитывать архивные и отменённые записи.

Перед выпуском scripts/backup_affirmations.py экспортирует историю из
public.planner_state, id=1 в новую JSON-копию. Транзакция READ ONLY,
REPEATABLE READ. Файл создаётся с правами 0600 и проверяется по SHA-256.
Существующий файл не перезаписывается. Проверка копии выполняется
аргументом --verify. Строка подключения передаётся через DATABASE_URL,
в копию и вывод команд она не попадает.

Порядок выпуска и отката описан в RELEASE_AFFIRMATIONS.md. Доступа к
рабочей Neon на этапе разработки нет, фактическая копия ещё не создана.

Проверки запускаются командой python -m unittest discover -s tests -v.
GitHub Actions использует изолированную PostgreSQL 16 без Telegram API.
Рабочую Neon эта ветка в тестах не использует.
